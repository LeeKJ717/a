# 0장 이 책의 작업대: 파이썬 환경, 가상환경, 폴더, 버전 관리, 그리고 되풀이할 수 있는 계산

제1권은 논문의 숫자를 손으로 다시 계산하며 읽었다. 그 계산을 컴퓨터로 되풀이한 스크립트가 장마다 하나씩 있다. 이 제2권은 독자가 그 스크립트를 자기 컴퓨터에서 처음부터 실행해 같은 숫자를 얻고, 그 위에 논문이 쓴 자료를 직접 내려받아 새로 분석하는 방법을 다룬다. 그러려면 먼저 작업대가 필요하다. 어떤 운영체제에서, 어떤 파이썬으로, 어떤 라이브러리 버전으로, 어떤 폴더 구조 안에서 계산했는지를 적어 두지 않으면, 한 달 뒤의 나도 같은 숫자를 얻는다고 장담할 수 없다.

이 장은 이 책이 실제로 쓴 작업대를 그대로 보인다. 모든 명령은 이 책을 쓴 컨테이너(가상 리눅스 컴퓨터)에서 실제로 실행했고, 이 장의 출력 숫자는 `ms/code/ch00/` 폴더의 실행 로그에서 옮겼다. 그런 다음 제1권 11장의 계산 스크립트를 새 가상환경에서 되풀이 실행해, 제1권 원고의 값과 맞는지 보인다.

**이 장이 하지 않는 것.**

- 이 장은 윈도우나 맥에서 실행하지 못했다. 이 책의 컨테이너는 리눅스(우분투 24.04)이다. 윈도우의 활성화 명령은 파이썬 공식 문서에서 읽은 것을 옮기며 "이 책이 실행하지 못함"으로 표시한다.
- 이 장은 다른 컴퓨터(다른 CPU, 다른 운영체제)에서 같은 로그의 해시가 나오는지 확인하지 못했다. 같은 컨테이너 안의 세 환경(시스템 파이썬, 가상환경 둘)에서만 확인했다.
- 이 장은 콘다(conda), 도커(Docker), 포에트리(Poetry), uv 같은 다른 환경 관리 도구를 다루지 않는다. 쓰지 않았으므로 설명하지 않는다.
- GPU 환경 구성은 10장에서 다룬다. 이 컨테이너에는 GPU가 없다.

**이 장에서 확인한 네 가지.**

1. 이 컨테이너의 시스템 파이썬은 3.13.16이고 numpy는 2.5.3이다. 새 가상환경에 numpy를 설치하면 같은 날 2.5.4가 깔렸다. 제1권 11장 스크립트의 출력 259줄은 numpy 2.2.6, 2.3.5, 2.5.3, 2.5.4(scipy 1.15.3, 1.16.3, 1.18.1)의 네 조합에서 한 글자도 다르지 않았다(SHA-256 해시 동일). 그러나 이것이 "버전은 상관없다"는 뜻은 아니다. 이 스크립트 하나에서, 이 컨테이너에서 그랬다는 것뿐이다.
2. 제1권 11장 스크립트를 네 번의 독립 실행과 재현 스크립트 한 번으로 되풀이했고 모두 같은 해시를 냈다. 제1권 원고의 값 14개를 대조해 14개가 모두 맞았다. 제1권과 어긋난 값은 없다.
3. 난수의 시드(seed)를 11에서 12로 바꿔도 출력은 한 글자도 바뀌지 않았다. 부트스트랩 반복 횟수를 2만에서 200으로 줄이자 비로소 값이 바뀌었다(0.464가 0.394로). 시드만 고정하면 된다는 흔한 믿음과 반대인 이 결과의 이유는 0.9절에서 설명한다.
4. 제1권 11장이 "논문 속 어긋남"으로 적은 것(표의 13.7%와 계산 16.7%, 23과 21 + 5 = 26 등)은 스크립트 출력에도 그대로 나온다. 되풀이하면 어긋남이 사라지는 것이 아니라, 같은 어긋남이 같은 자리에서 다시 나온다.

**명령을 읽는 법.** 이 책의 명령 상자에서 `$`는 "입력해 달라"는 표시이며 입력하지 않는다. 한 줄이 한 명령이다. 몇 가지 기호는 이 장에서 계속 나온다.

- `>`는 명령의 출력을 화면 대신 파일에 쓴다. `python3 calc.py > out.log`는 출력을 `out.log`에 저장한다. 같은 이름의 파일이 있으면 덮어쓴다.
- `|`(파이프)는 앞 명령의 출력을 뒤 명령의 입력으로 넘긴다. `pip list | grep numpy`는 설치 목록에서 numpy가 든 줄만 보인다.
- `&&`는 앞 명령이 성공했을 때만 뒤 명령을 실행한다. `||`는 앞 명령이 실패했을 때만 실행한다.
- `diff 파일1 파일2`는 두 파일이 다른 줄을 보인다. 같으면 아무것도 출력하지 않는다.
- `sha256sum 파일`은 파일의 SHA-256 해시를 출력한다.
- 명령이 끝나면 숫자 하나(종료 코드)가 남고, 0이면 성공이다. 스크립트는 이 숫자로 성공과 실패를 구분한다.

## 0.3 가상환경

<div class="theory" markdown="1">

#### 이론 배경: 가상환경과 requirements

컴퓨터에 설치된 파이썬(시스템 파이썬)에는 운영체제의 다른 프로그램이 의존하는 패키지가 섞여 있고, 새 패키지를 설치하면 그 버전이 모두에게 바뀐다. 프로젝트마다 필요한 버전이 다르면 서로 충돌한다. 가상환경은 이 문제를 피하려고 프로젝트마다 별도의 폴더에 파이썬 설치 공간을 만든다.

파이썬 공식 문서(Python Software Foundation, n.d.)는 가상환경을 "기존 파이썬 설치(기본 파이썬) 위에 만들어지며, 기본적으로 기본 환경의 패키지와 분리되어 가상환경에 명시적으로 설치한 것만 쓸 수 있는" 환경이라고 설명한다. 같은 문서는 가상환경을 "일회용으로 간주"하라고, 곧 지우고 처음부터 다시 만들기 쉬워야 한다고 적는다. 또 가상환경 안의 스크립트가 환경의 파이썬 경로를 절대 경로로 담고 있어서 "환경은 본래 옮길 수 없으며", 옮겨야 하면 새 위치에 다시 만들라고 경고한다. 이 책의 방식은 이 서술을 따른다. 가상환경 폴더는 결과물이 아니라 `requirements.txt`로 언제든 다시 만들 수 있는 것이다.

`requirements.txt`는 `패키지==버전`을 한 줄씩 적은 글이다. `pip freeze`는 지금 환경에 설치된 패키지를 이 형식으로 출력한다. pip 공식 문서(pip developers, n.d.)는 `pip freeze`가 "설치된 것을 보고할 뿐 잠금 파일이나 해(solver)의 결과를 계산하지 않는다"고 적고, 출력을 `pip freeze > requirements.txt`로 저장해 `pip install -r requirements.txt`로 다른 곳에서 설치하라고 안내한다. 같은 문서에 따르면 파이썬 3.12 이상에서는 `pip` 자신만 기본 출력에서 빠진다(`--all`로 포함).

**한계.** `requirements.txt`는 파이썬 버전, 운영체제, 컴퓨터의 CPU, 파이썬 밖의 시스템 라이브러리를 적지 않는다. 이 장의 실습이 보이듯 같은 버전 고정 아래에서도 다른 기계에서 같은 값이 나온다고 보증할 수는 없다. 그래서 이 책은 requirements와 함께 실행 환경(0.2절의 표)과 출력의 해시를 기록한다.

</div>

#### 실습 0-2. 가상환경을 만들고 requirements를 고정하기

**입력.** 인터넷에 연결된 컴퓨터, 파이썬 3.13.16. 필요한 패키지는 numpy와 scipy(제1권 11장 스크립트가 쓰는 것).

**명령.** 가상환경은 작업 폴더 밖에 둔다(이 책은 임시 폴더에 두었다). 아래는 이 책이 실행한 명령이며, `venv-ch00`은 가상환경 폴더의 이름이다.

```
$ python3 -m venv venv-ch00
$ source venv-ch00/bin/activate
$ which python
$ pip list
$ pip install numpy scipy
$ pip freeze > requirements.txt
$ pip list
$ deactivate
```

**결과(실행 로그 venv-create.log).**

- 가상환경 만들기: 2.71초.
- 켠 뒤의 `which python`: 가상환경 폴더 안의 `bin/python`. 버전은 3.13.16으로 시스템과 같다.
- 설치 전의 `pip list`: `pip 26.2.1`만 있다. 시스템 파이썬은 pip 24.0이었으므로, 가상환경이 만들어질 때 따로 들어온 pip의 버전이 다르다.
- `pip install numpy scipy`: 19.5초. scipy 1.18.1(35.3 MB)과 numpy 2.5.4가 설치되었다.
- `pip freeze`의 출력은 두 줄이다. 이것이 `requirements.txt`의 전부이다.

```
numpy==2.5.4
scipy==1.18.1
```

**확인.** 두 가지를 눈여겨본다. 첫째, 시스템 파이썬의 numpy는 2.5.3이었고 새 가상환경의 numpy는 2.5.4이다. 같은 컴퓨터, 같은 날, 같은 파이썬인데 버전이 다르다. 버전을 적어 두지 않았다면 이 차이는 드러나지 않았을 것이다. 둘째, 시스템 파이썬은 178개 패키지를 갖고 있지만 이 계산에 필요한 것은 두 줄이다. 가상환경은 "이 계산이 실제로 쓰는 것"을 두 줄로 드러낸다. (scipy는 numpy를 필요로 하므로 요구 사항 목록에는 두 줄이 모두 있다.)

윈도우 PowerShell에서는 파이썬 공식 문서가 `python -m venv C:\경로\venv`로 만들고 `<venv>\Scripts\Activate.ps1`로 켠다고 적는다. 스크립트 실행이 막혀 있으면 `Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser`를 먼저 실행하라는 안내도 같은 문서에 있다. 이 책은 윈도우에서 이 명령들을 실행하지 못했다.

#### 실습 0-3. requirements만으로 환경을 다시 만들기

| 폴더 | 들어 있는 것 | 손으로 고치는가 |

이 구성은 몇 가지 원칙을 따른다. 첫째, 원자료와 만든 것을 섞지 않는다. `data/`와 `geodata/`는 읽기만 하고, 계산 결과와 그림은 다른 폴더에 쓴다. 원자료를 고치면 어디서 고쳤는지 추적할 길이 사라진다. 둘째, 지울 수 있는 것과 지울 수 없는 것을 나눈다. `fig/`는 스크립트가 다시 만들 수 있으므로 지워도 되지만, 손으로 쓴 원고와 코드는 지울 수 없다. 셋째, 파일 이름에 밑줄을 쓰지 않고 하이픈을 쓰며, 버전을 이름에 넣는다(`-v1`). 이 책은 같은 이름으로 여러 판을 만들면 구별할 수 없기 때문에 판이 바뀔 때마다 번호를 올린다.

```
  code/                 계산 스크립트

```

## 0.5 버전 관리: git

<div class="theory" markdown="1">

#### 이론 배경: git

git은 폴더 안의 파일이 시간에 따라 어떻게 바뀌었는지를 기록하는 도구이다. 한 번의 기록을 커밋(commit)이라 하고, 커밋마다 고유한 번호와 설명 글이 붙는다. 이 도구를 쓰는 이유는 세 가지이다. 어느 줄을 언제 고쳤는지 알 수 있고(`git diff`), 고친 것이 잘못이면 되돌릴 수 있으며, 어느 시점의 코드로 어느 결과를 얻었는지 이름표(태그)로 묶을 수 있다.

git은 GNU 일반 공중 사용 허가서 2판(GPL 2.0)으로 배포된다고 git 공식 누리집이 밝힌다(Git, n.d.). 같은 페이지는 "Git"이라는 말과 로고의 사용은 제한한다고 덧붙인다. 이것은 상표에 관한 것이며 사용 허가와는 별개이다.

</div>

<div class="method" markdown="1">

#### 실습 0-4. 계산 스크립트를 git 저장소에 넣고 결과의 이력을 남기기

**입력.** 제1권 11장 스크립트 사본(`vol1-ch11-calc-v1.py`), `requirements.txt`.

**명령.** 임시 폴더에 저장소를 만들고 두 번 커밋한다. 이 책은 사용자 설정이 컨테이너의 전역 설정과 섞이지 않게 환경 변수 `GIT_CONFIG_GLOBAL=/dev/null`을 주고 실행했다. 독자의 컴퓨터에서는 처음 한 번 `git config --global user.name "이름"`과 `user.email`을 설정하면 된다.

```

$ git add .
$ git commit -m "계산 스크립트와 requirements 처음 기록"

$ git log --oneline

```

**결과(실행 로그 git-demo.log).** 두 줄의 `git log --oneline` 출력이 나왔다(커밋 번호는 시각이 들어가 실행마다 다르다. 이 책의 한 번 실행에서는 `0fb5c8a`와 `9c42f96`이었다). 태그 `ch00-demo`가 만들어졌다.

**확인.** `code/calc.py`의 내용과 `results/calc.log`가 같은 커밋에 묶여 있으면, 훗날 "이 로그는 어느 코드로 만든 것인가"에 답할 수 있다. 이 책의 규칙은 코드와 로그를 함께 커밋하는 것이다.

## 0.6 재현 가능한 분석의 원칙

Sandve 등(2013)은 「재현 가능한 계산 연구를 위한 열 가지 간단한 규칙」이라는 글에서 계산 분석의 재현에 필요한 규칙을 열 가지로 정리했다. 이 책은 PubMed Central의 원문 접속이 막혀 이 글을 직접 읽지 못했고(서지 확인 필요), 그 가운데 네 가지를 인용한 한 블로그 글(Wilke, 2013)에서 규칙의 이름만 읽었다. 읽은 네 가지는 "손으로 자료를 만지지 말 것", "중간 결과를 모두 기록할 것", "그림 뒤의 원자료를 보관할 것", "스크립트와 결과를 공개할 것"이다. 나머지 여섯 가지는 이 책이 읽지 못했으므로 적지 않는다.

이 책은 위의 네 가지와 이 장의 실습에서 직접 부딪힌 것을 합쳐, 다섯 가지 원칙을 세운다. 이것은 Sandve 등의 목록이 아니라 이 책의 작업 원칙이다.

{{T:이 책의 재현 원칙 다섯 가지와 이 장에서 그 원칙을 확인한 실습}}

| 번호 | 원칙 | 어기면 | 이 장의 확인 |
|---|---|---|---|
| 1 | 원자료는 읽기 전용으로 두고, 손으로 고치지 않는다 | 어느 값이 언제 바뀌었는지 모름 | 0.4절의 폴더 구분 |

## 0.7 제1권 계산을 처음부터 되풀이하기

제1권의 계산 스크립트는 `ch01-calc-v1.py`부터 `ch15-calc-v1.py`까지 있다. 이 가운데 11장(요하와 동북, 서요하의 아버지 계통, 퉁구스의 갈래, 노백산 나이테)의 스크립트 `ch11-calc-v1.py`를 골랐다. 고른 이유는 세 가지이다. 표준 라이브러리, numpy, scipy만 쓴다(0.3절의 requirements 두 줄로 충분). 난수를 쓰는 곳이 있다(부트스트랩, 시드 11). 제1권 원고에 같은 값이 계산 11-1부터 11-14까지 번호를 달고 적혀 있다.

이 스크립트는 입력을 모두 코드 안에 갖고 있어(논문 본문에서 옮긴 값) 외부 자료를 내려받지 않는다. 실행하면 259줄을 출력한다.

<div class="method" markdown="1">

#### 실습 0-5. 제1권 11장 스크립트를 세 환경에서 실행하고 출력을 비교하기

**입력.** `vol1-ch11-calc-v1.py`(제1권의 `ch11-calc-v1.py`의 사본). 사본이 원본과 같은 파일임을 SHA-256으로 확인했다(둘 다 `5f7062c7…c79c54`로 시작·끝남).

**명령.** 시스템 파이썬 한 번, 실습 0-2의 가상환경 한 번, 실습 0-3의 가상환경 두 번 실행해 출력을 파일로 저장하고 해시를 비교한다. `-I`는 파이썬의 격리 모드 옵션으로, 이 책은 모든 실행에 붙였다. 이 옵션이 정확히 무엇을 무시하는지는 파이썬 문서에서 읽지 못해 확인이 필요하며, 이 컨테이너에서는 `sys.flags.isolated`가 1로 나오는 것을 확인했다.

```
$ python3 -I vol1-ch11-calc-v1.py > run-system-1.log
$ venv-ch00/bin/python -I vol1-ch11-calc-v1.py > run-venva-1.log
$ venv-b/bin/python -I vol1-ch11-calc-v1.py > run-venv-1.log
$ venv-b/bin/python -I vol1-ch11-calc-v1.py > run-venv-2.log
$ sha256sum run-*.log
$ diff run-venv-1.log run-system-1.log && echo 같다
```

**결과(실행 로그).** 네 파일의 해시가 모두 같다.

```

4934a81284109d9085aa375f43ed91d9c405ca5c270561bf164b40c540b9362a  run-venv-2.log
4934a81284109d9085aa375f43ed91d9c405ca5c270561bf164b40c540b9362a  run-venva-1.log
```

`diff`는 아무것도 출력하지 않았다(출력 259줄이 모두 같다). 시스템 파이썬(numpy 2.5.3)과 가상환경(numpy 2.5.4)의 출력이 같다는 점이 중요하다. 스크립트 한 번의 실행 시간은 시스템 파이썬에서 0.98초, 0.95초, 0.94초였다.

**확인.** 해시가 같다는 것은 출력이 글자 하나까지 같다는 뜻이다. 이것은 "되풀이할 수 있다"를 보일 뿐 "맞다"를 보이지는 않는다. 맞는지는 0.8절에서 제1권 원고와 값을 맞춰 본다.

<div class="method" markdown="1">

#### 실습 0-6. 한 명령으로 처음부터 끝까지: 재현 스크립트

**입력.** `requirements.txt`, `vol1-ch11-calc-v1.py`, 기대 해시 파일 `expected.sha256`(실습 0-5의 해시), 점검 스크립트 `verify-vol1-v1.py`.

**명령.** 아래 스크립트 `repro-ch00-v1.sh`를 `bash repro-ch00-v1.sh`로 실행한다. 단계 하나가 실패해도 다음 단계로 가고, 마지막에 요약한다(셸의 `set -e`를 쓰면 한 단계 실패에 전체가 멈춘다. 이 책은 어느 단계가 실패했는지를 보려고 쓰지 않았다).

```
HERE="$(cd "$(dirname "$0")" && pwd)"
WORK="${1:-$(mktemp -d)}"
FAIL=0
step() { echo; echo "[단계] $1"; }
step "1 가상환경 만들기 ($WORK/venv)"
python3 -m venv "$WORK/venv" && echo "  성공" || { echo "  실패"; FAIL=1; }
step "2 requirements.txt 설치"
"$WORK/venv/bin/pip" install -q -r "$HERE/requirements.txt" 2>&1 | grep -v notice
"$WORK/venv/bin/pip" freeze > "$WORK/freeze.txt"
if diff -q "$HERE/requirements.txt" "$WORK/freeze.txt" >/dev/null; then echo "  설치된 버전이 requirements.txt와 같다"; else echo "  버전이 다르다"; FAIL=1; fi
step "3 계산 스크립트 실행"
"$WORK/venv/bin/python" -I "$HERE/vol1-ch11-calc-v1.py" > "$WORK/out.log" 2>&1 && echo "  종료 코드 0, $(wc -l < "$WORK/out.log")줄" || { echo "  실패"; FAIL=1; }
step "4 출력 해시 대조"
GOT="$(sha256sum "$WORK/out.log" | awk '{print $1}')"; WANT="$(cat "$HERE/expected.sha256")"
[ "$GOT" = "$WANT" ] && echo "  같다" || { echo "  다르다"; FAIL=1; }
step "5 제1권 원고와 대조"
"$WORK/venv/bin/python" -I "$HERE/verify-vol1-v1.py" "$WORK/out.log" /home/claude/book/ms/ch11-v1.md | tail -1
[ $FAIL = 0 ] && echo "요약: 모두 통과" || echo "요약: 실패한 단계가 있다"
```

(위는 지면을 줄여 첫 줄(`#!/usr/bin/env bash`), 일부 안내 출력과 제1권 원고 파일의 유무 검사를 뺀 것이다. 전체는 `ms/code/ch00/repro-ch00-v1.sh`에 있다.)

**결과(실행 로그 repro-run.log).** 다섯 단계가 모두 통과했다. 가상환경 만들기, 설치, 실행, 해시 대조(기대 `4934a812…`와 실제가 같다), 제1권 원고 대조(`일치 14 / 14`)까지 합쳐 19.2초가 걸렸다(최종 상태에서 다시 실행한 로그. 처음 실행은 더 짧았으나 그 로그는 덮어써서 남지 않았다). 종료 코드는 0이다.

**확인.** 독자가 할 일은 `bash repro-ch00-v1.sh` 한 줄이다. 제1권 원고의 경로(`/home/claude/book/ms/ch11-v1.md`)는 이 책의 컨테이너의 경로이므로, 독자의 컴퓨터에서는 원고가 없으면 5단계를 건너뛰고 나머지 단계만 돈다(스크립트는 파일이 없으면 "건너뜀"을 출력하게 되어 있다).

| 11-11 변이 하나의 햇수 | 1333.3년 | 1333.3년 | 일치 |

14개 항목이 모두 맞았다(`일치 14 / 14`). 제1권과 어긋난 값은 없다.

**제1권이 적은 "논문 속 어긋남"도 되풀이된다.** 제1권 11장은 논문의 값이 자체 산술과 맞지 않는 곳 네 군데를 경고로 적었다. 이 스크립트의 출력에서 그 줄을 찾아 확인했다.

- Cui 등(2013) 표 1의 우하량 C형과 O3a형: 표에는 13.7%, 계산은 1/6 = 16.67%(출력 `표에 적힌 빈도와 계산이 다른 곳`).
- 같은 논문의 실패 시료 수: 논문의 "23"과 21 + 5 = 26(출력 `실패 = 21 + 5 = 26 (논문 "23")`).
- Lyu 등(2016)의 부호 검정 (20, 9): 양쪽 p 0.0614, 한쪽 p 0.0307.
- Shelach-Lavi 등(2019)의 습윤 지속 기간: 가능한 범위 350~700년(출력 `최소 7.9 → 7.55 = 350년, 최대 8.1 → 7.4 = 700년`).

스크립트의 출력 가운데 "미결"이라는 글자가 들어간 줄은 7줄이다. 이 줄들은 스크립트가 해결하지 못했다고 스스로 적은 것이다. 되풀이한다고 미결이 풀리지는 않는다.

#### 실습 0-8. 같은 분포를 난수 없이 정확히 세기

**입력.** 대산전의 하플로그룹별 사람 수 [1, 3, 1, 2, 2](9명).

**명령.** `exact-boot-v1.py`는 9명을 복원추출해 얻을 수 있는 형별 수의 벡터를 모두 나열하고, 벡터마다 다항분포의 확률과 H를 구해 H의 정확한 분포를 만든다. 난수를 쓰지 않는다.

```
$ python3 -I exact-boot-v1.py
```

**결과(실행 로그 exact-boot.log).** 가능한 벡터는 715개이고, 서로 다른 H의 값은 17개이며 확률의 합은 1이다. 누적확률이 처음 2.5%, 50%, 97.5% 이상이 되는 H는 0.556, 0.778, 0.889이다. 제1권이 2만 번의 부트스트랩으로 얻은 값과 같다.

**확인.** H가 17개의 값만 가질 수 있으므로 2만 번의 모의에서 시드를 바꿔도 분위수가 바뀌지 않았다. 설명이 맞다는 것을 이 하나의 계산에서 확인했다. 다만 모의의 백분위수는 값 사이를 보간하고 위의 정확한 분위수는 누적확률이 처음 넘는 값을 고르는 방식이어서 정의가 다르다. 소수점 셋째 자리에서 일치했다는 것이 정의가 같다는 뜻은 아니다.

이것은 두 가지를 알려 준다. 첫째, 시드를 바꿔도 출력이 같은 것은 시드가 쓰이지 않아서가 아니라 반복이 충분히 많아 결과가 값의 가능한 범위 안에서 안정되었기 때문이다. 둘째, 그러므로 부트스트랩 결과의 소수점 자릿수는 반복 횟수가 정한다. 시드를 적는 것은 "정확히 같은 난수열"을 되풀이하려는 것이고, 반복 횟수를 적는 것은 "몇 자리까지 믿을 수 있는가"를 알리려는 것이다. 둘 다 적어야 한다. 이 시험을 계산 11-4 하나에서만 했으므로, 다른 계산에서도 같다고 말하지는 않는다.

## 0.10 한계와 함정

**해시가 같다는 것은 맞다는 뜻이 아니다.** 틀린 코드도 되풀이하면 같은 틀린 값을 낸다. 이 장은 0.8절에서 제1권 원고의 값과, 그리고 그 원고가 논문과 맞춘 값과 이어서 확인했다. 해시는 재현의 지문이고 정확성의 증명이 아니다.

**고정한 버전이 모든 것을 고정하지는 않는다.** `pip freeze`는 파이썬 버전, 운영체제, CPU, 선형대수 라이브러리의 구현을 담지 않는다. 이 책은 같은 컨테이너 안의 세 환경에서만 출력이 같음을 확인했다. 부동소수점 계산의 마지막 자리가 CPU나 라이브러리에 따라 다를 수 있다는 일반적 우려는 이 책이 다른 컴퓨터에서 확인하지 않았으므로 "확인 필요"로 둔다. 이 장의 스크립트는 소수점 아래 3~4자리만 출력하므로 마지막 자리의 차이가 출력을 바꿀 가능성은 낮지만, 낮다는 것이지 없다는 보증이 아니다.

**가상환경은 옮기지 않고 다시 만든다.** 0.3절에서 읽었듯 가상환경 안의 파일에는 절대 경로가 들어 있어 폴더를 옮기면 깨질 수 있다. 가상환경 폴더는 버전 관리에 넣지 않고(`.gitignore`) requirements로 다시 만든다.

**시스템 파이썬과 가상환경의 numpy가 달랐다.** 이 컨테이너에서 numpy는 2.5.3과 2.5.4가 함께 있었다. 이 장의 스크립트에서는 출력이 같았지만, 다른 계산에서도 그렇다는 보증은 없다. 버전을 적고 고정하는 이유가 이것이다.

**시간 측정은 흔들린다.** 이 컨테이너는 2코어이며 다른 작업과 자원을 나누어 쓸 수 있다. 스크립트 한 번의 시간은 0.94~0.98초로 비슷했지만, 10장에서 보듯 같은 스크립트를 두 번 실행한 시간이 두 배 가까이 다른 경우도 있었다. 시간을 적을 때는 한 번이 아니라 여러 번의 중앙값과 환경을 함께 적는다.

**이 장의 `-I` 옵션.** 격리 모드의 정확한 정의를 이 책이 파이썬 문서에서 확인하지 못했다. 다만 실습 0-9에서 `-I` 없이, 다른 폴더에서 실행해도 출력의 해시가 같음을 확인했다. 이 스크립트에서는 이 옵션이 결과를 바꾸지 않는다.
