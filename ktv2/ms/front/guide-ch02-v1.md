## 2장 안내: 논문과 자료를 모으는 법

**이 장이 묻는 것.** 제1권을 쓰면서 논문의 표를 글자로 바꾸면 열이 흩어져 나오는 일에 자주 걸렸고, 제1권 원고에는 "원문 쪽 확인 필요"가 25줄 남았다. 논문을 어떻게 찾고, 내려받고, 표를 꺼내고, 데이터베이스에 정리하면 그런 일을 줄일 수 있는가. 그리고 꺼낸 표가 맞는지를 어떻게 산술로 걸러내는가.

**길잡이.**

- 2.1~2.3절: 이 장의 말, OpenAlex와 Crossref의 이용 조건(2026년 10월 26일 WebFetch로 읽은 것만), 정중한 요청(간격, 연락처, 429와 403 처리). 실제 서버 호출은 하지 못했고(실습 2-0, 2-1), 가짜 서버로 요청 속도 조절을 시험했다(실습 2-2).
- 2.4~2.5절: SQLite 메타데이터 DB. 제1권 DB(papers 74줄, refs 109줄)를 읽고, DOI 정규화, 상태 열(cited, abstract, pdf), 출처끼리 다른 값을 덮어쓰지 않고 적는 충돌 표를 시연 자료로 끝까지 돌린다(실습 2-3~2-5).
- 2.6절: 제1권 조판 PDF의 표 36개에서 pdfplumber, pdftotext -layout, Camelot을 견준다(실습 2-6, 2-6b).
- 2.7절: 같은 표를 선 없이, 행 순서와 열 순서로 다시 조판한 PDF 108장에서 다섯 방법을 견주고, 실패 원인을 센다(실습 2-7, 2-7b, 2-7c).
- 2.8절: 흩어진 글자열에서 합과 비율을 제약으로 표를 되짜맞추고, 행 합, 열 합, 범위, 비율 점검 함수를 시험한다(실습 2-8).
- 2.9절 이후: 제1권과 맞는가, 한계와 함정, 도구와 라이선스, 실습 장부, 참고문헌.

**이 장의 숫자.** 실습 상자 15개(2-6b, 2-7b, 2-7c 포함), 그림 6개(색과 흑백 SVG 각 6장). 환경은 파이썬 3.13.16, pdfplumber 0.11.10, camelot-py 1.0.9, SQLite 3.45.1이고 GPU는 쓰지 않았다. 가장 오래 걸린 것은 재조판 PDF 108장 만들기(377.0초)이다. 본문의 한글 글자 수(공백 제외)는 약 1만 7천 자로 목표(2만 5천 자)에 이르지 못했다. 채우려고 늘리지 않았다.

**꼭 알아 둘 것.**

- 논문 API를 실제로 부르지 못했다(프록시가 403으로 거절). 호출 스크립트는 "실행 확인 필요(z840에서 실행)"이고, 가짜 서버와 시연값(가상 DOI 10.9999/...)으로 코드를 실행했다. 시연값의 숫자는 어떤 서비스나 논문의 증거가 아니다.
- API 한도는 문서 페이지끼리 어긋난다(OpenAlex의 초당 한도와 일일 무료 사용량, Crossref의 접근 페이지 표와 2025년 11월 공지). OpenAlex 데이터와 Crossref 메타데이터의 라이선스 이름, Unpaywall, SQLite의 라이선스는 확인하지 못했다.
- 제1권 조판 PDF에서 선 기준 추출이 394/394였던 것은 이 책이 선을 그어 조판했기 때문이다. 선이 없으면 0이었고, 파일에 쓰인 순서를 믿는 방법은 열 순서 PDF에서 0이었다. 학술지 PDF에서는 시험하지 못했다.
- 제1권과 어긋난 것 두 가지. 제1권 DB의 papers.doi 칸에 DOI가 아닌 `openalex:W3187374414`가 든 1줄(새 스키마는 ext_id로 따로 둠). Yang 등(2025)의 표 2 1986년 행이 AC + NC - 합계 = -0.02로 반올림 한계(0.015)를 넘고 글자열에도 같은 값이 있다. 원문 쪽 확인 필요.
- 상태 열의 대응에서 제1권의 meta, nopdf는 abstract인지 확인하지 못해 cited로 옮겼다. 새 DB의 z840 저장 위치(/data/safe/dball2/ktv_db)는 이 컨테이너에서 확인할 수 없다(z840 확인 필요).
- 눈으로 보지 못한 그림이 있다(흑백 4장: 흐름, 추출, 순서, 복원).

**앞뒤 장과의 연결.** 0장의 작업대(가상환경, 요구 사항 목록, 해시)를 쓴다. 이 장의 DB와 점검 함수는 이후 장에서 논문의 숫자를 다시 계산할 때 쓰는 입구이며, 제1권의 "원문 쪽 확인 필요" 줄(8장, 9장, 10장, 11장, 13장)을 줄이는 방법의 바탕이다. 이 장은 그 25줄에 방법을 적용하지 않았다.

**읽는 팁.** 코드를 따라 하려는 독자는 2.1절의 "코드 구성과 실행 순서" 표를 먼저 본다. 인터넷에 닿는 컴퓨터가 있으면 실습 2-1부터 하고, 없으면 2-3 이후는 이 책이 보낸 시연값과 제1권 PDF로 실행된다. 표 점검 함수(2.8절)만 필요하면 tablecheck.py의 네 함수를 먼저 읽는다.
